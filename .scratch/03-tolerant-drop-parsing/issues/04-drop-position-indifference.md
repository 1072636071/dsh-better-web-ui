# 落点无关性

**Status:** resolved

**Blocked by:** 02

**构建内容：** 外部拖入落在抽屉内任意位置都生效——包括已有的条目和分组头上，一律冒泡到面板级统一处理，效果等同落在空白区；抽屉内部的条目排序不受影响。

**验收标准：**

- [x] 外部拖入落在已有条目上 → 冒泡到面板统一处理，归属与落点无关
- [x] 外部拖入落在分组头上 → 同上
- [x] 抽屉内部排序拖拽仍然只做同组重排，不被外部拖入修复破坏
- [x] 条目级 drop 处理仅在内部排序拖拽进行中才拦截事件

## 评论

（评论与对话历史追加于此，新内容置于最前。）

- **resolved**（tolerant-drop-squad/engineer）。修复：`handleEntryDrop` 与 `handleEntryDragOver` 均以 `if (!dragIndex) return` 开头——仅内部排序拖拽进行中（dragIndex 非空）才 preventDefault/stopPropagation 并做同组重排；外部拖入不再被条目行吞掉，事件自然冒泡到面板级三级解析链统一处理，归属只取决于身份裁决。dragOver 同步收口：外部悬停条目不再显示条目级落点高亮，面板级 dragOver 高亮照常。测试 16 条全绿，新增 4 条：外部裸拖入落在已有条目上冒泡面板（归入未分组、原条目保留，先红后绿驱动）；落在分组头上同样生效；重复会话拖到条目上高亮去重不重建；内部排序同组重排仍生效且跨组拖放零副作用（不移动、不触发裁决）。

- 现状缺陷：条目行 drop 处理在任何状态检查之前就拦截事件，吞掉一切外部投放；抽屉填充后大部分面板面积是条目，故本工单是宽容解析真正可用的前提之一。
