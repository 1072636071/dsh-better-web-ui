# 未分组承接

**Status:** resolved

**Blocked by:** 02

**构建内容：** 散置会话不再被拒收。不属于任何工作目录的会话、以及侧边栏「未分组」桶头的拖入，都会自动创建或填充使用哨兵 id 的「未分组」分组。

**验收标准：**

- [x] 服务快照中无任何工作目录收录的会话拖入 → 归入「未分组」分组
- [x] 「未分组」桶头的键值拖入 → 「未分组」分组创建并填充全部未归组会话
- [x] 哨兵分组的去重、移除、折叠、排序行为与普通分组完全一致
- [x] 真实父工作目录存在的会话不会被误判为未归组

## 评论

（评论与对话历史追加于此，新内容置于最前。）

- **resolved**（tolerant-drop-squad/engineer）。核心契约核实：核心包 ui-workspace 的 `UNGROUPED_KEY = ''`（空串），桶头行 dragstart 经 `setData('text/plain', row.key)` 写入空串。据此：裁决层把空串裸文本识别为桶头信号（`kind: 'ungrouped-bucket'`），映射到抽屉侧哨兵键 `UNGROUPED_WORKSPACE_ID = '__ungrouped__'`（品牌化常量，定义于 drawer-store.ts，避免空串真值陷阱）；无归属会话走同款 `addEntry` 路径归入哨兵组；装配层 `collectUngroupedEntries` 在 drop 时从新鲜快照收集未被任何真实目录 sessionIds 收录的全部会话用于整组填充，复用既有 `addGroupWithEntries` 批量去重。测试 12 条全绿：新增 **5** 条——①未归组会话归哨兵组+持久化；②桶头键值建组且只收未归组成员（alpha/beta 不被误收）；③真实父目录会话不被误判；④哨兵组重复拖入高亮去重、折叠、移除随空消亡与普通分组一致；⑤哨兵组内条目拖拽排序与普通分组一致。〔计数勘误：初版评论误写「新增 4 条」，实际归属本票 5 条，t9 审查修正口径。〕
- 决策说明：①抽屉侧哨兵键取 `__ungrouped__` 而非照搬核心的 ''——核心键值只在「桶头拖入信号」这一处使用，抽屉 store/UI 侧用自文档化固定键更稳（workspaceId 为 UUID，无碰撞面）；②空串信号意味着任何 text/plain 为空的投放都会创建/填充哨兵组（无法与真实桶头区分）——这是 PRD 决策6「桶头键值按未归组信号处理」的直接推论，工单05 拒绝反馈不会覆盖空串路径；③typecheck 抓到哨兵常量缺品牌后已按宿主惯例断言补齐。收尾门槛：vitest 12/12 零错误、`tsc --noEmit` 退出码 0。

- 哨兵 id 是非真实 workspaceId 的固定键，标题固定为「未分组」；会话父目录归属由 workspaces 快照的 sessionIds 反查得出，反查不到即未归组（PRD 实现决策 5、6）。
