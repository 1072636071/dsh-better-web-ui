# PRD: 会话抽屉宽容拖入解析（Tolerant Drop Parsing）

Status: ready-for-agent

## 问题陈述

用户从侧边栏拖拽会话或工作目录到打开的会话抽屉后，没有任何反应。拖拽过程中抽屉明明亮起了"可投放"的高亮提示，松手却静默失败——既不创建条目，也不给出任何错误说明。用户无法区分"我不该拖这个"和"功能坏了"，对功能的信任被消耗。

根因是拖拽数据契约只有消费者没有生产者：抽屉只认规范载荷或带前缀的文本格式，而侧边栏行原生的裸拖拽只在 text/plain 里写了裸 id（且那是为侧边栏内部排序设计的）。工单 02「从侧边栏拖入条目」只实现了抽屉这半边就标记了完成。

## 解决方案

抽屉在收到投放时做宽容解析：优先识别规范载荷与前缀格式，均未命中时把裸 id 交给 sessions/workspaces 服务快照裁决身份——是会话就归入其真实父工作目录分组，是工作目录就创建并填充该分组，都不命中才给拒绝反馈。不属于任何工作目录的会话与「未分组」桶头自动归入哨兵 id 的「未分组」分组。全程零核心包改动，仍是纯插件。

## 用户故事

1. 作为多会话用户，我想要从侧边栏拖拽一个会话到打开的抽屉面板，以便将它加入快速切换列表
2. 作为多项目用户，我想要从侧边栏拖拽一个工作目录头到抽屉面板，以便将该目录连同其下全部会话一次性纳入管理
3. 作为拥有未归组会话的用户，我想要拖入不属于任何工作目录的会话时它被自动收进「未分组」分组，以便不因缺少归属而被拒收
4. 作为用户，我想要拖拽侧边栏「未分组」桶头时自动创建并填充「未分组」分组，以便批量收纳散置会话
5. 作为用户，我想要拖入的会话自动归入其真实父工作目录分组（分组不存在则自动创建），以便抽屉分组始终镜像工作目录结构
6. 作为用户，我想要拖入已存在的会话条目时不产生重复、改为已有条目高亮闪烁，以便知道它已在管理中
7. 作为用户，我想要拖入已存在的工作目录分组时同样高亮该分组而不重复创建
8. 作为用户，我想要在拖入无法识别的内容（如一段普通文本）时看到面板红框闪烁加轻微抖动的拒绝反馈，以便明确知道操作被拒绝而非系统无响应
9. 作为用户，我想要把会话拖到抽屉内任意位置（包括落在已有条目上）都生效，以便不必瞄准空白区（落点无关性）
10. 作为用户，我想要拖拽悬停抽屉时继续看到蓝色边框高亮与投放提示，以便确认此处可投放
11. 作为用户，我想要抽屉内的条目拖拽排序保持原样可用，以便外部拖入的修复不影响既有整理能力
12. 作为用户，我想要页面刷新或重启后拖入的条目仍然保留，以便无需重复添加
13. 作为用户，我想要侧边栏自身的拖拽排序行为完全不变，以便本次修复不带来任何回归
14. 作为开发者，我想要上述行为有回归测试保护，以便拖拽数据契约再次脱节时测试先行报警而非用户报障

## 实现决策

### 架构约束

1. **零核心包改动**：遵守 ADR-001 与 ADR-003。核心包拖拽源头（侧边栏行）不修改，`application/x-dsh-drag` 规范载荷保留为无生产者的快速路径。
2. **只动插件包**：变更集中在会话抽屉插件的三个单元——抽屉组件、抽屉 store、插件客户端装配层。不为测试改动生产代码结构，不新增 seam。
3. **裁决权威**：宽容解析的唯一权威是 sessions/workspaces 服务快照，不依赖核心包 DOM 结构或样式类名。

### 解析链

4. **三级解析顺序**：规范载荷 MIME（JSON）→ 前缀 text/plain（`session:`/`workspace:`）→ 宽容裁决（裸 id 对照服务快照）。前两级维持现状，第三级为新增。
5. **会话归属反查**：拖入会话的父工作目录由 workspaces 快照中各目录的 sessionIds 反查得出；反查不到即视为未归组。
6. **未分组分组**：使用哨兵 id（非真实 workspaceId）作为分组键，标题固定为「未分组」；侧边栏「未分组」桶头的键值同样按未归组信号处理。
7. **去重语义不变**：跨全部分组按 sessionId 去重，命中即高亮闪烁已有条目/分组，约 1.2 秒自动消退（沿用现有机制）。

### 交互修正

8. **落点无关性**：抽屉条目行的 drop 处理仅在内部排序拖拽进行中才拦截事件；外部拖入一律冒泡到面板级统一处理，归属与落点无关。
9. **拒绝反馈**：纯 CSS 动画（红色边框闪烁 + 轻微抖动）加组件本地状态驱动，约 1 秒后自动消退；不依赖任何通知基建。
10. **悬停高亮不变**：dragOver 期间的蓝色边框与空态提示文案维持现状。

### 测试基建

11. **新增开发依赖**：vitest、jsdom、@testing-library/react 加入插件包 devDependencies，package.json 增加 test 脚本；这是本仓库第一批测试。

## 测试决策

1. **单一 seam**：一切用例经由插件客户端入口边界（注入内存假 services + 真 store + 真组件）驱动，合成 HTML5 拖拽事件（stub dataTransfer 的 getData）作用于渲染出的 DOM。
2. **只测外部行为**：断言渲染出的分组/条目文本与数量、CSS 反馈类（高亮闪烁、拒绝反馈）的出现与消退、store 状态与 localStorage 持久化写入；不断言内部函数调用或实现细节。
3. **覆盖矩阵**：裸会话拖入建组归组；裸目录拖入填充；未归组会话与桶头归「未分组」；重复拖入高亮不重建；未知文本触发拒绝反馈且不改状态；落点在已有条目上仍生效（冒泡）；内部排序在同一用例中确认不受影响。
4. **先例**：DSH 核心仓库 ui-workspace 包的行组件测试（vitest + testing-library 风格）为本决策的样式参照；本仓库自身无既有测试。

## 超出范围

1. 核心包的任何改动，包括让侧边栏 dragstart 直接写规范载荷（ADR-003 已否决）
2. 「落点即插入位」语义——外部拖入不支持指定插入位置，条目定位仍走抽屉内部排序
3. 全局 toast / 通知服务的引入与调研
4. 从抽屉向外拖出条目、抽屉与侧边栏之间的反向拖拽
5. 为规范载荷实现生产者（保留为未来快速路径）
6. 清理持久化中指向已删除会话/工作目录的陈旧条目
7. 侧边栏内部排序行为的任何改动
