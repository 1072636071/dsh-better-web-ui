# ADR-003: 侧边栏拖入采用抽屉侧宽容解析

## 状态

已决策 (2026-08-22)

## 背景

会话抽屉（ADR-001）的工单 02「从侧边栏拖入条目」只实现了消费端：抽屉的 `parseDragData` 认两种格式——自定义 MIME `application/x-dsh-drag`（JSON）或带 `session:`/`workspace:` 前缀的 `text/plain`。但全仓库不存在任何生产者：核心包 `ui-workspace` 的 `Rows.tsx` 在 dragstart 时只写裸 id 到 `text/plain`（会话行写 `node.id`，工作目录行写 `row.key`），且这是为侧边栏内部排序设计的。用户从侧边栏拖会话/工作目录进抽屉，解析失败后 `handleDrop` 静默返回，表现为"没有任何反应"。

## 决策

**不改核心包拖拽源头**，在抽屉插件内做宽容解析：drop 时若前缀协议与自定义 MIME 均未命中，将 `text/plain` 裸 id 拿到 `sessions` / `workspaces` 服务快照中裁决——命中会话即按会话处理（父工作目录由服务侧归属关系解析），命中工作目录即按工作目录处理，两者皆不命中才忽略。`application/x-dsh-drag` 规范载荷保留为未来快速路径。

## 被否决的替代方案

1. **改核心包 Rows.tsx 在源头写规范载荷**：数据流最干净，但违反 ADR-001「纯插件不修改核心包」约束，核心包被插件协议反向耦合。
2. **插件侧 dragstart 桥接**（文档级监听补写 `x-dsh-drag`）：协议显式、可复用，但多一套监听机制，且身份裁决同样依赖服务快照——复杂度更高而信息增量相同。

## 后果

- **正面**：零核心改动，修复落在插件内解析/装配/store 三单元 + 测试基建；服务快照是身份裁决的唯一权威，不依赖核心包 DOM 结构或类名。
- **负面**：拖拽契约是隐式的（裸 text/plain + 服务快照），核心包若改变 dragstart 写入内容（如改写人类可读标题），解析会再度静默失效。
- **缓解**：`application/x-dsh-drag` 规范载荷保留为快速路径；解析失败路径需要可见反馈（另行动决策）。
