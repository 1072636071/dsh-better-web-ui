# ADR-001: 两层 Tab 架构（外层=工作目录，内层=会话）

## 状态

已决策 (2026-08-20)

## 背景

DSH 当前对话区（center column）一次只展示一个会话，无法同时维持多个会话的上下文。用户需要一种方式将多个会话和工作目录以标签页形式并排管理，类似于浏览器标签页或 VSCode editor group。

## 决策

在对话区顶部实现**两层 tab strip**：

- **外层 tab**：代表工作目录（workspace）。切换外层 tab = 切换整个工作目录上下文，内层 tab 随之切换为该目录下的会话列表。
- **内层 tab**：代表工作目录内的会话（session）。切换内层 tab = 切换当前展示的具体会话。

## 被否决的替代方案

1. **只装会话（单层 session tab）**：每个 tab 是一个 session，不分工作目录。简单直接，但多项目并行时缺乏上下文隔离，会话混杂。
2. **只装工作目录（单层 workspace tab）**：tab 代表 workspace，切换后仍需在侧边栏选会话。信息密度低，和侧边栏功能重叠。

## 后果

- **正面**：完整的多工作区多会话管理，适合多项目并行场景
- **负面**：交互复杂度翻倍（两层状态管理），实现量较大，需要处理外层/内层联动、tab 溢出等问题
- **风险**：两层 tab 在窄屏下可能挤占空间，需要设计好溢出策略
