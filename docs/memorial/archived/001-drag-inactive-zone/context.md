# 001 · 拖拽会话/工作目录到不活跃区

## 诉求

> 做一个 DSH 插件：对回话框进行调整，可以通过拖拽等方式，把工作目录和回话放到不活跃区。

## 追问记录

### Q1 · 「不活跃区」的产品形态 [2026-08-20]

**提问**：不活跃区是什么？视觉收纳区、隐藏归档、视觉降级、还是独立面板？

**用户回答**：把当前的对话区再做一个折叠设计——不另辟新区域，让对话区自身具备折叠能力。

**调研事实**：
- 当前 DSH 三栏布局（sidebar | conversation | details），对话区是 center column
- 侧边栏已有 collapse 到 56px rail 的能力，对话区没有类似机制
- 侧边栏已有会话/工作目录的拖拽重排序（HTML5 drag-and-drop）

### Q2 · 折叠的位置和形态 [2026-08-20]

**提问**：折叠发生在对话区的什么位置？顶部标签条、侧翼折叠栏、底部抽屉、还是手风琴？

**用户回答**：**顶部标签条（tab strip）**——对话区顶部一行 tab，活跃会话占主体，不活跃的折叠成 tab。拖拽到 tab 区即可折叠，点击 tab 切换回来。

### Q3 · tab 的粒度：工作目录 vs 会话 [2026-08-20]

**提问**：tab strip 里装的是会话、工作目录、还是两层？

**用户回答**：**两层 tab**——外层 tab 是工作目录，内层 tab 是会话，类似 VSCode editor group。

**分析**：
- 满足三条件的 ADR：难以逆转（两层结构一旦确立，单层方案无法兼容）、有被否决的替代方案（单层会话 tab、单层工作目录 tab）、未来读者会惊讶（为什么选最复杂的方案）
- 需要创建 ADR-001

### Q4 · 拖拽交互流 [2026-08-20]

**提问**：会话/工作目录怎么进入 tab strip？侧边栏拖入、单击开 tab、还是混合模式？

**用户回答**：**侧边栏拖入**——从侧边栏拖 session 到内层 tab bar 创建 session tab；拖 workspace header 到外层 tab bar 创建 workspace tab。

**推论**：侧边栏单击行为需要单独定义（见后续追问）。

### Q5 · 侧边栏单击行为 [2026-08-20]

**提问**：引入 tab 后，侧边栏单击 session 的行为是什么？

**用户回答**：**单击 = 替换当前活跃 tab** — 在当前 tab 内导航到新 session（类似浏览器在当前 tab 里打开新链接）。没有活跃 tab 时直接打开。

### Q6 · tab 关闭方式 [2026-08-20]

**提问**：怎么从 tab strip 移除一个 tab？

**用户回答**：**tab 上的 × 按钮** — 每个 tab 右侧的关闭按钮，hover 时显示。和浏览器/VSCode tab 一致。

### Q7 · 内层 tab 溢出策略 [2026-08-20]

**提问**：内层 session tab bar 放不下时怎么处理？

**用户回答**：**滚动横条** — 单行滚动，两端渐隐箭头提示。

### Q8 · 外层 tab 溢出策略 [2026-08-20]

**agent 自行决策**：外层 workspace tab 采用**相同策略（滚动横条）**。虽然 workspace 数量通常较少（3-5 个），但统一两层溢出逻辑降低实现复杂度，未来 workspace 增多时也不需要切换方案。

### Q9 · tab 拖拽重排序 [2026-08-20]

**agent 自行决策**：**支持拖拽重排序**，两层各自内部可拖拽调整顺序。理由：侧边栏已有成熟的 HTML5 拖拽重排序模式（`DragState`、`RowDragProps`），可复用相同交互范式；tab 不可重排是常见痛点，实现成本低。不支持跨层拖拽（不能把 session tab 拖到另一个 workspace tab 下）。

### Q10 · tab 状态持久化 [2026-08-20]

**agent 自行决策**：**页面刷新保留，DSH 重启不保留**。使用 `localStorage` 存储当前打开的 tab 列表（workspace ID + session ID），刷新后恢复。DSH 重启时 session 由后端重新分配，旧 tab 引用可能失效，不强制恢复。
